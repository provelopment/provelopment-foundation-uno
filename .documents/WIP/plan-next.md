## One unissued candidate

**Owner-controlled integration of a validated `base` into the real single-Site configuration, with explicit
Site/Page publication and a full-locale policy (candidate only, not issued).** A later bounded stage could take
the now-validated canonical base and its explicit aliases, decide which one is the Owner's actual public
origin, integrate it into the existing single-Site declaration without inventing a second configuration
authority, and only then prove real production HTTP behaviour, emitted metadata and honest refusal of
unpublished addresses.

Three boundaries carry forward and may not be inferred from the work now complete: validating a base is not
choosing a production domain, a declared base is not a published Site, and an alias is a note for a later
redirect decision — not a redirect, a domain claim or an ownership assertion.

One content caveat is recorded here so it cannot be forgotten: the committed Home Markdown still contains
outdated statements about selection and source reading and is **not approved for publication as-is**. Correcting
it needs a later Owner-approved content change, not a side effect of any configuration work.

That work needs its own Owner-installed work order, its own exact-path ledger and its own independent tests on
both hosts; nothing in this note authorises it.
